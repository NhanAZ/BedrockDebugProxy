# AUDIT-0014 - Bounded ordered capture writer

- Commit subject: `Decouple capture writes from packet forwarding`
- Change type: `runtime`
- Runtime impact: `yes`

## Intent

Prevent disk-backed capture work from stalling the forwarding callbacks during high-volume server-to-client bursts. The
fix targets the Galaxite session where a dense `UpdateBlock` burst preceded a `You moved too slow` write failure.

## Scope

`internal/capture/recorder.go` now assigns sequence numbers at submission and drains one bounded ordered writer queue.
The queue exposes record and byte bounds, blocks rather than dropping evidence, and records its policy and peak occupancy
in manifest values. `RecordReader` is a synchronous barrier after queued events, and `Close` drains accepted jobs before
publishing the final manifest. `internal/proxy/proxy.go` checks asynchronous recorder failures from the forwarding loop,
and forward timing documentation now distinguishes capture submission from writer commit. Packet bytes, decoded views,
packet ordering, resource-pack handling, transfer routing, and capture schema remain unchanged.

## Evidence and provenance

The owner-provided Galaxite capture `captures/session-20260916T060203Z` was generated by revision
`320478f65db244c8b4d8be05e756e2c7774289db`. It retained 489,910 events and 93,790 blobs with zero dropped, truncated,
decode, or capture write errors, but contained 40,259 decoded `UpdateBlock` packets and rare 596 to 738 ms record/write
stalls before a `You moved too slow` bridge write failure. The implementation follows the bounded-writer and visible
counter design evidence documented from EndstoneMC spyglass, while retaining this project's lossless capture invariant.
No external source code was copied.

## Known limitations and follow-up

The queue changes when capture events become durable, not what bytes are captured. A full queue still blocks forwarding,
and a single record larger than the byte budget is admitted when the queue is empty. The capture still does not expose raw
RakNet acknowledgements, retransmissions, or client-side chunk application. If Galaxite remains slow after this change,
compare the stamped proxy capture with a direct-client capture before changing protocol or transport behavior.
