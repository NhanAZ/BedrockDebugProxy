# Audit AUDIT-0177

- Intent: capture resource packs offered during a live upstream login without requiring a local listener or a second Minecraft client.
- Scope: add `run --packs-only`, reuse the existing upstream dial and resource-pack capture path, add an opt-in gophertunnel dial completion boundary at the resource-pack exchange, retain optional live viewer and decryption behavior, add mode-specific capture metadata and lifecycle evidence, and update CLI help, README, resource-pack documentation, fork provenance, research, fix history, and changelog.
- Affected interfaces: `run` adds `--packs-only`. The mode rejects explicit `--listen`, `--follow-transfers`, and `--allow-unauthenticated-client`. The local gophertunnel fork adds `Dialer.ResourcePackExchangeOnly`, which returns after `ResourcePackStack` is accepted and the final `PackResponseCompleted` is flushed. Capture manifests identify `operation_mode: packs_only`, omit `listen_address`, identify `client_metadata_source: gophertunnel_default`, and successful runs add `resource_pack.fetch_complete` with pack count, protocol, game version, and `world_spawned: false`. Existing archive and packet event schemas are unchanged.
- Evidence and provenance: gophertunnel `v1.61.0` at `283a5a97dfe65da94bcc0b401807f6aefa9e72ee` was the API baseline; inspection of the BedrockDebugProxy fork showed its ordinary `DialContextNetwork` return is later than the separate `Conn.DoSpawn` API suggests. The fork's opt-in completion hook and reader stop are recorded in `third_party/gophertunnel/BEDROCKDEBUGPROXY_PATCH.md`. Reviewed bedrocktool `85d5cfe1545c8d853be2859144a8357539ffc0f2` and maintainer-authorized private EasySpecter `6939f8aa1ad70fc694d370e3b4b33e6d3e49482c` as references. No third-party source was copied. Detailed findings are in `docs/research/resource-pack-fetch-mode.md`.
- Automated validation: `tools/quality.ps1 -LowMemory` passed on the final implementation, including formatting, module and license checks, all Go tests, build, `golangci-lint` (0 issues), vulnerability scanning (0 reachable vulnerabilities), tracked capture artifact checks, and whitespace checks. The scanner also listed 4 imported packages and 2 required modules whose reported vulnerabilities are not called by this code. `TestRunPacksOnlyCapturesUpstreamWithoutListener` passed with a loopback Bedrock listener offering one archive and exercising the pack-only runner, including archive SHA-256 and capture integrity. `TestDialerResourcePackExchangeOnlyStopsBeforeWorldStartup` passed repeatedly while a test server sent `StartGame`; it verified that no chunk-radius or local-player initialization packet was sent. The focused CLI help and invalid-option tests passed.
- Live validation: not run. A controlled local server check should confirm archive checksum equality and no spawn request. A fresh stamped The Hive baseline is required before release approval under the project gate.
- Known limitations: packs-only mode still performs a real upstream login that the server may record or reject. It uses default client metadata, which can result in a different pack offer than a specific client would receive. It does not capture gameplay or packs offered only after world spawn. The fifteen-minute upstream login and resource-pack deadline applies. Captures and optional decrypted output contain sensitive identity and pack data.
- Follow-up: build and run the repository quality gate, then perform a controlled local-server validation and the required stamped The Hive baseline before considering this runtime-affecting change release-ready.
