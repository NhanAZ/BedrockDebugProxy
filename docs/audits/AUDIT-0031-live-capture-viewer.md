# AUDIT-0031 - Follow captures in the web viewer

- Commit subject: `feat: add live capture viewing`
- Change type: `runtime | tooling | documentation`
- Runtime impact: `yes - optional local viewer lifecycle only`

## Intent

Let an operator use the browser interface as the primary packet research view while Minecraft is connected, without attaching browser latency or failure to proxy forwarding.

## Scope

Add incremental open-capture indexing, tail pagination, one-second browser polling, a visible live and final verification state, `view --live`, and `run --web-viewer`. Extract loopback HTTP server lifecycle into a reusable viewer component. Update the viewer documentation and architecture record.

The proxy transports, packet forwarding, authentication, recorder ordering, capture schema, canonical event and blob formats, artifacts, protocol definitions, and default `run` behavior are unchanged. Terminal lifecycle and compact packet summaries remain available. No dependency or external browser asset is added.

## Evidence and provenance

- The maintainer requested live browser observation after reviewing the closed capture viewer.
- ADR 0009 records the boundary between committed capture-file reads and packet forwarding.
- `internal/capture/recorder.go` writes blob content before the event line that references it and closes the manifest only after the ordered asynchronous writer drains.
- The implementation extends the independent viewer introduced in AUDIT-0030. No additional third-party source or asset was copied.

## Validation

- Automated checks: `pass - tools/format.ps1, tools/quality.ps1, focused viewer and CLI race tests, JavaScript syntax check, live loopback smoke check, and git diff --check`
- Live validation: `not_observed - the optional viewer lifecycle does not change transport or forwarding behavior`
- Capture or report: `synthetic open and closed captures generated by internal/viewer tests, plus a local view --live loopback smoke check against a previously verified closed capture`

## Limitations and follow-up

The browser polls once per second and the in-memory row index grows with the number of observed events. Live counts are observations, not a verification result. Final integrity status is available only after the capture manifest closes. The integrated HTTP server exits with the proxy process, while the canonical capture remains available for later offline viewing.
