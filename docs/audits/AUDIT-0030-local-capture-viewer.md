# AUDIT-0030 - Add a local capture viewer

- Commit subject: `feat: add a local capture viewer`
- Change type: `runtime | tooling | documentation`
- Runtime impact: `yes - offline viewer only`

## Intent

Make saved packet evidence practical to explore visually while preserving the existing capture-first architecture. Provide the packet list, filters, decoded details, byte view, and navigation needed for research without attaching a UI to the live forwarding path.

## Scope

Add the `internal/viewer` package with an embedded browser interface, a lightweight event index, paginated filtering, on-demand event reads, and bounded blob previews. Add the `view` CLI command, automatic default-browser opening, loopback-only HTTP serving, per-run access paths, restrictive response headers, tests, documentation, an architecture decision, and an Unreleased changelog entry.

The proxy runner, network transports, authentication, protocol definitions, recorder, capture schema, canonical files, automatic artifacts, and forwarding logs are intentionally unchanged. No external JavaScript package, web font, service, or new Go dependency is added.

## Evidence and provenance

- The maintainer requested implementation after reviewing the research value and interface quality of EndstoneMC Spyglass.
- EndstoneMC Spyglass revision [`8fb7e2cdd888b591382ad4d002e08390f3685d83`](https://github.com/EndstoneMC/spyglass/tree/8fb7e2cdd888b591382ad4d002e08390f3685d83), licensed MIT, was reviewed for its packet list, filter, decoded tree, byte pane, navigation, counter, and bounded-store behavior.
- This is an independent web implementation over BedrockDebugProxy's existing `bedrockdebugproxy.capture.v1` files. No Spyglass source or assets were copied.
- ADR 0008 records why the viewer is restricted to closed captures and kept separate from packet forwarding.

## Validation

- Automated checks: `pass - tools/format.ps1, tools/quality.ps1, JavaScript syntax check, focused viewer and CLI tests, loopback HTTP smoke check, and git diff --check`
- Live validation: `not_observed - the change does not alter proxy forwarding or capture writing`
- Capture or report: `synthetic captures generated by internal/viewer tests and one uncommitted closed-capture CLI smoke check`

## Limitations and follow-up

Startup hashes every referenced blob and holds one compact row per event in memory. The viewer is intended for local closed captures and does not tail an active session. Blob previews stop at 64 KiB and the decoded browser tree stops after 4,000 nodes. These display bounds do not change canonical evidence. A future change should use measured large-capture evidence before replacing the index or adding live updates.
