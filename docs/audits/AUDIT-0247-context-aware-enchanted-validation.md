# Audit 0247 - Context-aware Enchanted validation

- Intent: replace the fixed Enchanted child and mandatory-hop release wording with a route-aware workflow that follows the server's current Hub form.
- Scope: `AGENTS.md`, `CHANGELOG.md`, `docs/decisions/0016-context-aware-enchanted-validation.md`, `docs/releasing.md`, `docs/server-targets.md`, `docs/validation.md`, `validation/README.md`, `tools/create-validation-report.ps1`, `tools/check-release-readiness.ps1`, and `cmd/bedrock-debug-proxy/validation_test.go`.
- Runtime impact: none. The proxy, protocol codecs, transport behavior, capture schema, and resource-pack implementation are unchanged.
- Policy: agents inventory and classify the current Enchanted form, test each actionable top-level child from a fresh Hub session, inspect nested forms, follow every observed `Transfer`, and return to the Hub before the next top-level child. A route without `Transfer` is classified from its observed context rather than treated as an automatic failure.
- Report contract: Enchanted reports require `enchanted_form_review=pass` and `enchanted_route_matrix=pass`. `transfer_following` and `resource_pack_transfer` accept `pass` or the explicitly justified `not_applicable` state. At least one playable route must still reach spawn and stability, and the normal automatic integrity, authentication, pack, traffic, and closure gates remain in force.
- Related catalog correction: `Steal a Mob` is removed from the Enchanted child workflow; `Rob a Mob` is documented as a separate Featured Experience.
- Evidence and provenance: source review found that the previous current workflow named OP SMP and unconditionally required transfer checks. The maintainer supplied the current Enchanted form behavior and requested context-aware traversal. The implementation adds synthetic pass/fail coverage for both transfer-applicable and transfer-not-applicable Enchanted reports.
- Automated validation: `go test ./...`; `tools/quality.ps1 -LowMemory`; `git diff --check`.
- Live validation: `not_applicable`; this commit changes release policy, report validation, documentation, and tests only. No public-server runtime behavior changed.
- Limitations: the sanitized report stores manual review states rather than raw form payloads or the complete route ledger. Agents must retain the sensitive route ledger locally or in the approved private evidence workflow and must not place raw form data, addresses, credentials, packet payloads, resource-pack keys, or decrypted assets in the report.
- Follow-up: the next Enchanted release run must build a stamped binary, inventory the live form, test its current actionable routes, generate the aggregate review evidence, and use `not_applicable` only for conditional flows proven absent by that run.
